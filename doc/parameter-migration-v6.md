# v6 Parameter Namelist Migration

The v6 parameter format is intentionally not backward compatible. Parameter
namelists now use named derived values generated by nml-tools 0.5, and each
active process registers its own parameters during component configuration.

## Tuple Conversion

The old five-column order was:

```fortran
lower_bound, upper_bound, value, optimization_flag, scaling
```

The new derived-type buffer order is:

```fortran
value, optimize, min, max
```

For example:

```fortran
! old
PET_c = -2.0, 0.0, -0.7, 1, 1

! new, with schema bounds
pet_c = -0.7, .true.

! new, with explicit bounds
pet_c = -0.7, .true., -2.0, 0.0
```

Every parameter schema provides its established minimum and maximum. A
single `value` uses those bounds and keeps `optimize = .false.`. Adding
`.true.` enables optimization with the schema bounds. The full four-value
form overrides the bounds. Values remain required in every form.

The application owns `parameter_t` in `mo_parameter_types`; nml-tools imports
that type when generating parameter namelist modules. Programmatic v6 callers
must replace `%lower_bound` with `%min` and `%upper_bound` with `%max`.

The old scaling column was removed because it had no effective use in the
current optimization calls. Numeric optimization flags migrate as `0` to
`.false.` and `1` to `.true.`.

## Geological Parameters

`GeoParam` is now the `baseflow_recession` array in `baseflow_1`. Every
geological unit must still provide a value; bounds are broadcast from the
schema through `items.default`.

```fortran
! old row: lower, upper, value, flag, scaling
GeoParam(1,:) = 1.0, 1000.0, 100.0, 1, 1

! new
baseflow_recession(1) = 100.0, .true.
```

## Removed Entries

- `PTF_Ks_curveSlope` is no longer configurable. The MPR legacy adapter uses
  the fixed inch/hour to centimetre/day conversion constant `60.96`.
- `gain_loss_GWreservoir_karstic` was removed. The v6 formula uses only
  `recharge_coefficient` and `karstic_recharge_factor`.
- The fifth scaling value was removed from every parameter.

## Runtime Contract

Only selected process namelists are read. Components register process-local
definitions in deterministic execution order and consume current values with a
named lookup. Calibration still sees one flat array; processes no longer know
their global offsets. Restart files containing precomputed MPR or routing state
reject parameter overrides that the restart would otherwise hide.

## Final Forward Parameters

The named registry can write its current values, or a supplied complete
optimizer result, as a reduced parameter namelist:

```fortran
call parameters%write_namelist("final_parameters.nml")
call parameters%write_namelist("final_parameters.nml", optimized_values)
```

The output contains only the namelist blocks registered by the selected
processes. Each entry records the final value, whether it participated in
optimization, and the bounds used:

```fortran
&pet_m1
  pet_c =      -0.700000000000,  .true.,      -2.000000000000,       0.000000000000
/
```

Names and tuple columns are aligned, and real values use twelve decimal places
as in the v5 final-parameter output. Values that do not fit the fixed field use
scientific notation. The result is suitable for a subsequent forward run:

```bash
mhm-driver --parameters final_parameters.nml
```

Writing an explicit result vector does not change the registry's current
values or calibration metadata. The reduced file preserves parameter
selection and bounds, but it is not an optimizer checkpoint and does not retain
optimizer state, objective settings, or progress.

Regenerate and check the schema outputs with:

```bash
nml-tools generate --config nml-config.toml
nml-tools check --config nml-config.toml --diff
```
